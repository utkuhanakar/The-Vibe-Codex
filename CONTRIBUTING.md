# Contribution Guidelines

Thank you for considering contributing to the **Awesome Engineering & Vibe Coding** repository! 🎉

To keep this list highly curated, useful, and professional, please follow these guidelines when submitting a Pull Request (PR).

## 🛑 Golden Rules

1. **Search First:** Check if the repository or tool is already listed.
2. **Quality Over Quantity:** We only accept repositories that are actively maintained, have good documentation, and solve a real problem.
3. **Context is King:** Do not just add a link. You **must** provide a short, objective description of what it does and *why* it is useful.

## 📝 How to Add a Repository (Categories)

If you are adding a tool to one of the files in the `/categories/` folder, use the following format:

> - [Repository Name](https://github.com/link) - A clear, concise, objective description. (Optional: *Why it matters / Best for X*).

**Example:**
- [bat](https://github.com/sharkdp/bat) - A `cat` clone with syntax highlighting and Git integration. *Best for modern terminal workflows.*

## 🧠 How to Add a Prompt (Prompts)

If you have a killer AI prompt for the `/prompts/` section, ensure it follows this structure:
1. **The Problem:** What is the AI failing to do?
2. **The Prompt:** The exact text you use.
3. **The Result:** What the prompt achieves.

## 🔄 Pull Request Process

1. Fork the repo and create your branch from `main`.
2. Ensure your formatting matches the surrounding markdown perfectly.
3. Update the Table of Contents if you created a completely new file.
4. Submit the PR with a clear title (e.g., `Add Next.js to Web Architecture`).

*By contributing, you agree that your additions will be licensed under the same license as this repository.*
